## Estrutura de atuação

Este perfil organiza meu trabalho em quatro frentes complementares:

- programação de IA como parte executável do sistema, e não apenas como interface conversacional
- construção de runtimes, módulos e ferramentas em Nim para modelos locais e serviços de inferência
- desenvolvimento de interfaces transparentes em JavaScript puro, HTML, CSS e DOM nativo
- aplicação dessa base em produtos educacionais, sistemas empresariais e fluxos operacionais reais

## Static Next: estado como programa

O protocolo que orienta meu trabalho recente de frontend pode ser resumido assim:

```text
next(patch)
  → retoma o generator
  → aplica o patch ao estado
  → produz o próximo root DOM
  → substitui o root anterior
  → mantém o programa vivo no iterator
```

Essa estrutura evita separar artificialmente estado, renderização e continuidade. O componente não simula um lifecycle: ele é um programa suspenso e retomado pelas próprias primitivas do JavaScript.

## IA como parte do runtime

Nos projetos em Nim, a IA é tratada como uma dependência operacional com fronteiras claras:

```text
entrada
  → contrato/signature
  → chamada do modelo
  → seleção ou execução de ferramenta
  → validação
  → trace
  → estado e saída da aplicação
```

O objetivo é produzir software em que o comportamento do modelo possa ser chamado, observado, testado e composto como qualquer outra parte relevante do sistema.

## Fechamento

Meu foco atual é transformar IA em material prático de programação: modelos, ferramentas, estado, traces e interfaces participando do mesmo fluxo executável.

Nim sustenta a parte compilada de agentes, módulos e runtimes. JavaScript puro sustenta interfaces diretas e legíveis por meio de generators, iterators e DOM nativo. Entre os dois, procuro construir sistemas completos com pouca indireção, comportamento observável e espaço real para evolução.
